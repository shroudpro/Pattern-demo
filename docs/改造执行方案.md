# 纹生万象最终版五轮改造方针

> 本文基于 `改造方案.md`、当前项目结构和 `public/img` 新增视觉素材整理。目标不是直接进入编码，而是给后续大改造提供清晰、可验证、可分阶段交付的工程方针。

**目标定位：** 将现有“AI 东方纹理设计产品”改造为“AI 汉字文化意象可视化系统”。

**核心产物：** 用户输入一个汉字后，系统生成一张包含真实中文排版、文化解析内容、意象背景和可编辑图层的“汉字文化解析图”。

**推荐路线已确认：**

- 前端继续使用当前 `Next.js 15 + React 19`，不迁移 Vue。
- 3D 先做稳定视觉版，再升级真实 Three.js。
- 数据库短期保留现有表，通过 payload 升级语义；中期再补完整新表。
- Editor 继续基于 Fabric，改成解析图微调与导出工具。
- API 保留现有 `/api/v1/*` 骨架，新增或扩展 infographic 语义，不做破坏性重命名。

---

## 一、当前项目基线

### 1. 可复用部分

当前项目已经具备最终版需要的主流程骨架：

- `src/app/create/page.tsx`
- `src/app/analyze/[sessionId]/page.tsx`
- `src/app/generate/[sessionId]/page.tsx`
- `src/app/editor/[projectId]/page.tsx`

后端也已有对应基础能力：

- `backend/app/api/routes/analysis.py`
- `backend/app/api/routes/image.py`
- `backend/app/api/routes/project.py`
- `backend/app/service/character_analysis_service.py`
- `backend/app/service/image_generation_service.py`
- `backend/app/service/project_editor_service.py`

已有本地字库：

- `src/lib/mock/character-analysis.json`

已有编辑器：

- `src/features/editor/FabricEditorShell.tsx`

已有图片生成链路：

- `backend/app/service/prompt_composer_service.py`
- `backend/app/providers/dashscope_image.py`
- `backend/app/providers/mock.py`

这些部分不建议推倒重来，应该在现有结构上做语义升级。

### 2. 必须改造部分

当前项目仍保留旧定位：

- Generate 页仍强调“纹理图”“海报”“包装”。
- 数据结构仍以 `designKeywords`、`commonImages`、`classicalPoems` 为主，缺少解析图需要的完整字段。
- 图片模型生成的是背景纹理，不是解析图生成链路的一部分。
- Editor 是通用设计编辑器，仍有上传图片、自由添加文本等功能。
- Analyze 页是信息卡片页，不是“3D 汉字文化星图”。

### 3. 工作区风险

当前工作区存在大量未跟踪缓存和 `.codex/skills` 删除状态。后续编码前必须先隔离工作区：

- 不直接在脏工作区做大改造。
- 推荐新建独立分支或 git worktree。
- 不批量删除 `.npm-cache`、`.next`、`__pycache__` 等缓存，除非先列出路径并得到确认。

## 二、素材映射规则

新增素材位于：

```text
public/img
```

前端引用路径统一使用：

```text
/img/A1.png
```

不要写成：

```text
public/img/A1.png
```

因为 Next 静态资源从 `public` 根目录映射到站点根路径。

### 1. 素材清单

| 代号 | 文件路径 | 用途 | 建议使用位置 |
| --- | --- | --- | --- |
| A1 | `/img/A1.png` | 全局深色主背景 | 全站基础背景、Analyze、Generate、Editor 外层 |
| A2 | `/img/A2.png` | 宣纸纹理叠加层 | 全站 texture overlay、解析图纹理层 |
| A3 | `/img/A3.png` | 云气透明叠加层 | Analyze 背景、解析图氛围层 |
| B1 | `/img/B1.png` | Create 页入口主视觉 | Create 页主背景 |
| C1 | `/img/C1.png` | Analyze 页字海背景图 | 字海底层背景 |
| C2 | `/img/C2.png` | Analyze 页中心汉字光场背景 | 中心汉字背后光效 |
| D1 | `/img/D1.png` | 传统风格 16:9 解析图背景模板 | traditional + 16:9 默认背景 |
| D2 | `/img/D2.png` | 现代风格 16:9 解析图背景模板 | modern + 16:9 默认背景 |
| E1 | `/img/E1.png` | Editor 页默认画布背景 | Editor 外层或画布工作区背景 |
| F1 | `/img/F1.png` | “山”字 16:9 文化解析图示例成品 | 演示占位、答辩 fallback、生成前预览 |

### 2. 使用原则

- 页面背景优先用素材，不再继续依赖旧 `public/design` 素材。
- 解析图背景模板优先用 D1、D2 作为 16:9 稳定 fallback。
- 生成链路未接通或图片 API 失败时，S 级演示字“山”可使用 F1 做答辩展示 fallback。
- A2、A3 应作为透明叠加层，避免直接遮挡正文。
- 解析图正文必须由系统真实渲染，不允许让图片模型生成中文正文。

## 三、五轮改造总览

| 轮次 | 目标 | 关键结果 | 风险等级 |
| --- | --- | --- | --- |
| 第 1 轮 | 产品语义和数据结构重构 | 项目从“纹理设计”转成“汉字文化解析” | 中 |
| 第 2 轮 | Generate 页改成解析图生成配置 | 风格 + 比例 + 解析图项目创建链路跑通 | 高 |
| 第 3 轮 | Editor 改成解析图微调导出 | 默认图层、文字可调、PNG 可导出 | 中高 |
| 第 4 轮 | Analyze 页视觉升级 | 字海、中心汉字、文化星图稳定落地 | 高 |
| 第 5 轮 | 质量、答辩、fallback 闭环 | S 级演示、构建验证、降级方案完整 | 中 |

执行原则：

1. 先改最终产物，再做视觉爆点。
2. 先保留可运行闭环，再逐步增强效果。
3. 每轮结束都必须能跑通 Create 到 Editor 的主流程。
4. 不把图片模型用于生成中文正文。
5. 每轮改造都要同步更新测试或验证命令。

## 四、第 1 轮：产品语义和数据结构重构

### 目标

把现有“东方纹理生成”语义改为“汉字文化解析任务”，建立解析图所需的数据基础。

这一轮不追求 3D，不追求解析图最终视觉，只解决“系统到底在生成什么”的根问题。

### 前端改造范围

#### 1. Create 页

涉及文件：

- `src/app/create/page.tsx`
- `src/features/create/CreateEntryForm.tsx`
- `src/lib/design/content.ts`

改造方向：

- 背景从旧 `DESIGN_ASSETS.createBackground` 切换到 `/img/B1.png`。
- 页面主标题保留“纹生万象”。
- 增加副标题：“AI 汉字文化意象可视化系统”。
- 输入提示从“进入文化解读”改为“生成文化解析”。
- 推荐字库继续复用 `RECOMMENDED_CHARACTERS`，但展示优先 S 级演示字。

建议 Create 页文案：

```text
一字一世界，万象由此生。
输入一个汉字，探索它的字源、意象、诗意与视觉形态。
```

#### 2. 全局视觉素材入口

新增或调整：

- `src/lib/design/content.ts`

建议新增：

```ts
export const FINAL_ASSETS = {
```

保留旧 `DESIGN_ASSETS`，但新页面逐步迁移到 `FINAL_ASSETS`，避免一次替换导致页面大面积失控。

### 后端改造范围

#### 1. 扩展分析 schema

涉及文件：

- `backend/app/schema/analysis.py`
- `src/types/analysis.ts`

旧结构：

```text

imageryAnalysis

classicalPoems

```

新结构建议：

```text

visualMotifs
colorPalette
atmosphereTags

```

其中 `poems` 必须结构化：

```json
{
  "line": "会当凌绝顶，一览众山小。",
  "author": "杜甫",
  "title": "望岳",
  "explanation": "表现登临高处后的胸襟与气势。"
}
```

#### 2. 保持兼容

因为现有本地字库字段暂时不完整，需要提供适配层：

- 如果本地数据只有 `classicalPoems: string[]`，先转换为 `poems`。
- 如果缺少 `modernMeaning`，可从 `shuowenExplanation` 和 `summary` 临时生成简短版本。
- 如果缺少 `visualMotifs`，从 `commonImages` 转换。
- 如果缺少 `backgroundPromptKeywords`，从 `visualMotifs`、`atmosphereTags`、`colorPalette` 组合。

这一层应放在：

- `backend/app/service/character_analysis_service.py`

不要让前端承担旧字段兼容。

### 本地字库改造

涉及文件：

- `src/lib/mock/character-analysis.json`

第一轮只人工重写 S 级演示字，不要一次重写 100+ 字。

建议 S 级优先 12 字：

```text
山、水、月、风、云、竹、茶、龙、礼、和、梦、光
```

每个 S 级字必须补齐：

- `subtitle`
- `modernMeaning`
- `poems`
- `visualMotifs`
- `colorPalette`
- `atmosphereTags`
- `forbiddenElements`
- `layoutPriority`
- `backgroundPromptKeywords`

### 测试要求

涉及文件：

- `backend/tests/test_character_services.py`
- `backend/tests/test_new_api_skeleton.py`

新增测试点：

- 创建“山”的 analysis session 后，返回 `modernMeaning`。
- 返回 `poems` 且每条包含 `line`、`author`、`title`、`explanation`。
- 返回 `visualMotifs` 且不少于 3 项。
- 本地字库命中时不调用外部文本模型。
- 旧字段兼容不会导致接口 500。

### 第 1 轮验收标准

- Create 页新定位文案生效。
- `/api/v1/analysis-sessions` 返回新版解析字段。
- “山”字数据完整。
- Analyze 页即使仍是旧卡片，也能展示新版文化字段。
- 后端测试通过。

## 五、第 2 轮：Generate 页改成解析图生成配置

### 目标

Generate 页从“生成纹理图”改成“生成汉字文化解析图配置页”。

这一轮是产品差异化的关键。必须让用户看到系统要生成的是解析图，而不是背景图。

### 前端改造范围

涉及文件：

- `src/app/generate/[sessionId]/page.tsx`
- `src/features/generate/GenerateWorkbench.tsx`
- `src/types/generation.ts`
- `src/lib/api/client.ts`
- `src/lib/formatters/display.ts`

#### 1. 删除旧场景选项

移除前台：

```text
poster
package
```

新增比例选项：

```text
16:9
1:1
9:16
```

建议类型：

```ts
export type InfographicRatio = "16:9" | "1:1" | "9:16";
export type InfographicStyle = "traditional" | "modern";
```

#### 2. Generate 页文案

旧文案：

```text
将文化解读转译为可用于海报与包装的东方纹理图
```

新文案：

```text
选择解析图风格与比例，系统将生成包含真实中文排版、文化解析内容和意象背景的汉字文化解析图。
```

按钮文案：

```text
生成文化解析图
重新生成解析图
进入微调导出
```

#### 3. 预览区域

生成前：

- 如果字符是“山”且比例为 16:9，可展示 `/img/F1.png` 作为示例预览。
- 其他字符展示 D1 或 D2 背景模板，并覆盖“待生成解析图”的状态层。

生成后：

- 展示系统合成后的解析图预览。
- 不再只展示背景图。

### 后端改造范围

建议保留现有 `image-generation-jobs`，新增 infographic 语义服务。

新增文件：

- `backend/app/schema/infographic.py`
- `backend/app/service/infographic_layout_service.py`
- `backend/app/service/background_generation_service.py`
- `backend/app/service/infographic_project_service.py`

可选新增路由：

- `backend/app/api/routes/infographic.py`

推荐 API：

```text
POST /api/v1/infographic-projects
GET /api/v1/infographic-projects/{project_id}
POST /api/v1/infographic-projects/{project_id}/regenerate-background
```

如果短期不新增路由，也可以复用 `/api/v1/projects`，但 payload 必须加 `projectType: "infographic"`。

### 背景生成规则

图片模型只生成无文字背景。

传统风格 prompt：

```text
Chinese cultural infographic background, ink landscape atmosphere, rice paper texture, visual motifs: {visualMotifs}, color palette: {colorPalette}, no text, no typography, no logo, no readable characters
```

现代风格 prompt：

```text
modern museum infographic background inspired by Chinese character imagery, subtle grid, low saturation, visual motifs: {visualMotifs}, no text, no typography, no logo, no readable characters
```

负面提示词必须包含：

```text
readable text, Chinese characters, typography, logo, watermark, poster title, wrong calligraphy, random glyphs
```

### 比例尺寸规则

建议尺寸：

| 比例 | 宽 | 高 | 用途 |
| --- | ---: | ---: | --- |
| 16:9 | 1920 | 1080 | 答辩大屏 |
| 1:1 | 1400 | 1400 | 作品集 |
| 9:16 | 1080 | 1920 | 手机传播 |

如果图片 provider 对尺寸有限制：

- 背景图使用 provider 支持尺寸生成。
- 系统合成阶段再裁切或铺底到目标画布。

### LayoutSpec

新增 `LayoutSpec`，作为解析图排版引擎的核心中间层。

建议字段：

```json
{
  "canvas": {
    "width": 1920,
    "height": 1080,
    "ratio": "16:9"
  },
  "style": "traditional",
  "background": {
    "imageUrl": "/img/D1.png",
    "opacity": 1
  },
  "layers": [
    {
      "id": "main-character",
      "type": "text",
      "role": "mainCharacter",
      "text": "山",
      "left": 820,
      "top": 140,
      "width": 280,
      "height": 280,
      "fontSize": 240
    }
  ]
}
```

### 第 2 轮验收标准

- Generate 页没有“海报/包装”前台选择。
- 用户可以选择 `traditional / modern`。
- 用户可以选择 `16:9 / 1:1 / 9:16`。
- 点击生成后创建的是解析图项目。
- 图片模型 prompt 明确禁止文字。
- “山 + traditional + 16:9”可稳定生成或 fallback 到 D1/F1。

## 六、第 3 轮：Editor 改成解析图微调与导出

### 目标

把 Editor 从通用设计编辑器改为“解析图微调与导出页”。

这一轮必须让用户一进入编辑器就看到完整解析图，而不是空画布加背景。

### 前端改造范围

涉及文件：

- `src/app/editor/[projectId]/page.tsx`
- `src/features/editor/FabricEditorShell.tsx`
- `src/types/project.ts`
- `src/lib/api/client.ts`

建议新增组件：

- `src/features/editor/InfographicEditorShell.tsx`
- `src/features/editor/LayerPanel.tsx`
- `src/features/editor/InspectorPanel.tsx`
- `src/features/editor/ExportPanel.tsx`

短期可以在 `FabricEditorShell.tsx` 内部改造，稳定后再拆分。

### 页面布局

采用三栏结构：

```text
左侧：图层列表
中间：解析图画布
右侧：属性面板
底部：导出与返回修改
```

外层背景使用：

```text
/img/E1.png
```

### 默认图层

解析图项目创建时必须自动生成以下图层：

```text
background
paperTexture
cloudOverlay
mainCharacter
subtitle
shuowenBlock
modernMeaningBlock
imageryBlock
poemBlock
motifTags
brandMark
```

16:9 traditional 默认布局：

- 背景：`/img/D1.png`
- 主字：画布中左偏上，大字号宋体或楷体风格
- 左侧：说文解字 + 现代释义
- 右侧：意象分析
- 底部：诗词关联
- 右下：纹生万象标识

16:9 modern 默认布局：

- 背景：`/img/D2.png`
- 主字：中心偏左或顶部中心
- 内容：网格化信息卡片
- 颜色：低饱和、清晰、高对比

### 需要保留的功能

- 选择图层。
- 拖动文字模块位置。
- 修改标题/副标题/诗词文本。
- 修改字号。
- 修改字体。
- 修改文字颜色。
- 调整背景透明度。
- 导出 PNG。
- 自动保存项目 payload。

### 需要隐藏或弱化的功能

当前编辑器里的这些功能不应作为主入口：

- 上传图片。
- 随意添加文本框。
- 自由贴图。
- 包装样机。

处理方式：

- 第 3 轮先隐藏上传图片。
- “添加文本框”改为“添加注释层”，并限制为解析图内部注释。
- 删除选中元素保留，但关键图层删除前需要二次确认或改为隐藏。

### 后端改造范围

涉及文件：

- `backend/app/schema/project.py`
- `backend/app/service/project_editor_service.py`
- `backend/app/api/routes/project.py`

项目 payload 建议扩展：

```json
{
  "projectType": "infographic",
  "character": "山",
  "style": "traditional",
  "ratio": "16:9",
  "backgroundImageUrl": "/img/D1.png",
  "canvasWidth": 1920,
  "canvasHeight": 1080,
  "layoutSpec": {},
  "elements": []

```

### 导出方式

短期：

- 继续用 Fabric 的 `canvas.toDataURL()` 导出 PNG。

中期：

- 前端用 `html-to-image` 或后端导出服务统一输出。

答辩阶段优先保证浏览器导出稳定，不急着做后端导出。

### 第 3 轮验收标准

- 从 Generate 进入 Editor 后，画布上已经有完整解析图图层。
- 用户可以选中并调整文字模块。
- 上传图片入口默认不可见。
- 导出 PNG 可用。
- 刷新页面后项目元素仍保留。

| 时间 | 效果 | 实现 |
| --- | --- | --- |
| 0-1.5 秒 | 字海浮现 | CSS absolute 小字粒子 |
| 1.5-2.5 秒 | 目标字高亮 | Framer Motion scale/glow |
| 2.5-4 秒 | 镜头推进 | 容器 scale + blur 减弱 |
| 4-5.5 秒 | 中心成字 | 主字放大 + C2 光场 |
| 5.5-7 秒 | 星图展开 | SVG path + 卡片入场 |
| 7 秒后 | 稳态阅读 | 中心字轻微浮动 |

```text
                诗词关联
                   ↑

                   ↓
```

四个卡片内容：

## 八、第 5 轮：质量、答辩和 fallback 闭环

### 目标

保证比赛展示稳定，补齐降级方案、验证命令、答辩证据链和演示路径。

### S 级演示闭环

必须优先保证：

```text
山 → Analyze → Generate traditional 16:9 → Editor → 导出 PNG
```

“山”字 fallback：

- Analyze 数据来自本地人工校验。
- Generate 背景优先 D1。
- 生成失败时使用 F1 作为示例成品展示。
- Editor 仍能打开一个完整解析图项目。

### 外部 API 降级

文本模型失败：

- S 级字使用本地数据。
- A 级字使用本地数据 + 字段兼容。
- B 级开放字提示“当前字未命中本地精品库，可尝试重新生成或切换演示字”。

图片模型失败：

- traditional + 16:9 使用 `/img/D1.png`。
- modern + 16:9 使用 `/img/D2.png`。
- 其他比例用 D1/D2 居中裁切或纯色渐变 fallback。

Editor 导出失败：

- 提示用户重试。
- 保留画布可截图。
- 不阻塞项目数据保存。

### 答辩证据链

答辩时必须强调：

1. 系统不是普通图片生成器。
2. 汉字文化内容先结构化，再驱动视觉生成。
3. 图片模型只生成无文字背景，中文由系统真实渲染。
4. Editor 不是通用设计平台，而是解析图微调工具。
5. 本地 S 级字库保证现场演示稳定。

推荐答辩主线：

```text
输入一个汉字 → 本地文化知识库优先 → 文本模型补位 → JSON 校验 →
无文字背景生成 → 系统中文排版 → 解析图项目 → 可编辑导出
```

### 第 5 轮验收标准

- `山` 的完整演示链路稳定。
- 无网络或 API 失败时仍有可展示结果。
- 构建和后端测试通过。
- 页面文案不再出现“包装”“通用海报设计平台”等旧定位。
- 答辩可清楚解释系统和 GPT Image / Canva 的区别。

## 十、不可做事项

以下事项会破坏最终版定位或增加无效风险：

- 不迁移到 Vue。
- 不让图像模型直接生成中文正文。
- 不把 Generate 页继续做成海报/包装选择器。
- 不把 Editor 宣传成自由设计平台。
- 不在第 1 轮就做真实 Three.js 字体挤出。
- 不一次性重写 100+ 字本地字库。
- 不批量删除缓存、依赖或生成文件。
- 不在未隔离工作区的情况下开始大规模改造。

## 十一、最终执行优先级

优先级从高到低：

1. 解析图数据结构。
2. Generate 页语义转向。
3. 解析图默认图层生成。
4. Editor 微调导出。
5. Analyze 字海星图。
6. Three.js 增强。
7. 开放字外部模型补位。
8. 数据库完整表结构升级。

核心判断：只要第 1 到第 3 项完成，项目就已经从“纹理设计平台”变成“汉字文化解析图系统”。Analyze 的 3D 是加分项，但不能替代核心产物改造。
